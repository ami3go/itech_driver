# Ordered integration audit

This is a disposable Git merge audit, not an integrated release or hardware test. PRs #2–6 plus all primary review PRs #78–148, excluding closed duplicates #135/#137, are attempted in numerical dependency order. The already merged migration #1 is included in the master baseline. The workflow fetches all PR refs before merging, freezes their SHAs and records the base, per-PR result, conflict files, diagnostics and resulting tree SHA. It never pushes. A failed merge is aborted, then the audit continues to identify further conflicts; a later successful merge can include ancestors of a skipped PR, so the report requires semantic interpretation. A clean audit does not establish correctness. Conflicts are intentionally a failing check; download the JSON artifact and resolve shared files semantically on a separate integration branch, then run full offline CI. The workflow now exports a hash-bound source archive after a clean audit, then executes only offline tests on isolated GitHub-hosted runners. Do not run driver code on a physical bench. No HIL, no deployment, no release. Run manually only in a disposable checkout: python tools/audit_integration.py --base <master-sha> --output integration-audit.json.

The integrated regression jobs verify the snapshot digest, compile the source, install dependencies, collect and run non-hardware pytest, check dependencies and build a wheel on Windows/Linux Python 3.10/3.13. Each job publishes JUnit and build artifacts. This is not a physical qualification or release.
